# Блог — плагин motorchk

Записи блога с рубриками и тегами для [motorchk](https://github.com/burzilov/motorchk): список записей, страница
записи, редактор в админке. С плагином [i18n](https://github.com/burzilov/motorchk-plugin-i18n) — записи на
нескольких языках; без него — один язык сайта.

**[Скачать](https://github.com/burzilov/motorchk-plugin-blog/releases/latest)** — последний ZIP из GitHub Releases
(распаковать в `public_html/plugins/`).

Версия 0.1.0, ядро `^0.5` (проверено на 0.5.6), PHP 8.4. Лицензия — [MIT](LICENSE).

## Установка

1. Скачать `blog-X.Y.Z.zip` и распаковать в `public_html/plugins/` — получится `public_html/plugins/blog/plugin.json`.
2. Включить плагин в админке («Плагины»). При установке создаются пустые `posts.json`, `categories.json`,
   `tags.json` в `plugin-data/blog/`.
3. В админке появится пункт меню «Блог». Ссылку на `/blog/` добавить в меню сайта обычным пунктом.

## Обновление

Релизы — в [GitHub Releases](https://github.com/burzilov/motorchk-plugin-blog/releases): тег `vX.Y.Z`, архив
`blog-X.Y.Z.zip`, внутри папка `blog/` с `plugin.json`. Имена тега и архива фиксированы; поле
`"repository": "burzilov/motorchk-plugin-blog"` в `plugin.json` указывает, где искать обновления. Обновить вручную:
скачать архив, удалить `public_html/plugins/blog/` и распаковать архив в `public_html/plugins/`. Данные
в `plugin-data/blog/` при этом не трогаются.

## Адреса

| Адрес | Что |
|-------|-----|
| `/blog/` (`?page=N`) | опубликованные записи, новые сверху, 10 на странице |
| `/blog/{slug}` | запись |
| `/blog/category/{slug}` | записи рубрики |
| `/blog/tag/{slug}` | записи с тегом |

С i18n те же адреса на других языках: `/en/blog/`, `/en/blog/{slug}` и т. д. Несуществующая запись, рубрика, тег
или страница списка — 404 в шаблоне темы. Черновики гостям не видны (404), администратору — видны.

Адрес (slug): латиница в нижнем регистре, цифры и дефисы, до 80 символов. Пустой — составляется из заголовка
(транслитерация). У записей заняты `category`, `tag`, `page`, `new`; у рубрик и тегов — `new`.

## Админка

«Блог» → вкладки «Записи», «Рубрики», «Теги».

- Запись: заголовок, анонс и текст (Markdown, как в страницах ядра), адрес, дата, рубрика (одна), теги (любое
  число), «Опубликовать». Без отметки — черновик.
- Смена адреса рубрики или тега переносится во все записи; удаление снимает рубрику/тег с записей.
- Все формы — POST с CSRF-токеном ядра; ошибки проверки показываются в форме, введённое не теряется.

## Данные

`plugin-data/blog/`:

- `posts.json`, `categories.json`, `tags.json` — объекты «адрес → запись». Если файл повреждён, сайт показывает
  блог без этих данных, админка пишет, какой файл повреждён, и ничего не сохраняет, пока его не восстановят
  (например, из резервной копии плагина backup).
- `settings.json` — необязательные настройки (правится вручную):

```json
{
    "per_page": 10,
    "template": "default",
    "menu_location": "",
    "styles": true
}
```

| Поле | Что | По умолчанию |
|------|-----|--------------|
| `per_page` | записей на странице, 1–50 | `10` |
| `template` | шаблон темы для страниц блога (`[a-z0-9_-]`) | `default` |
| `menu_location` | какое меню темы показывать (пусто — основное) | `""` |
| `styles` | подключать `assets/blog.css` | `true` |

## Подключение к теме

HTML блога выводится в шаблоне темы (`template`, по умолчанию `default.php`) на месте содержимого страницы —
как у страниц ядра. Заголовок и описание (`<title>`, meta description = анонс записи) ставит ядро.

Для оформления — классы: `blog`, `blog--list`, `blog--post`, `blog-title`, `blog-meta`, `blog-card`,
`blog-card__title`, `blog-card__excerpt`, `blog-card__more`, `blog-pagination`, `blog-body`, `blog-back`,
`blog-empty`. Базовые стили — `assets/blog.css`; со своими стилями темы его можно отключить (`"styles": false`).

Шаблону темы доступен `$pluginVars['blog']`:

- `type` — `list`, `category`, `tag`, `post` или `not_found`;
- для списков: `term` (`slug`, `name` или `null`), `page`, `pages`;
- для записи: `post` — `slug`, `url`, `title`, `excerpt`, `date`, `date_label`, `published`, `category`
  (`slug`, `name`, `url` или `null`), `tags` (список `slug`, `name`, `url`).

Например, подсветить пункт меню или убрать боковую колонку: `<?php if (($pluginVars['blog']['type'] ?? '') === 'post'): ?>`.

## Мультиязычность (i18n)

- Если плагин i18n установлен, в редакторе — поля заголовка, анонса и текста на каждом языке сайта, у рубрик
  и тегов — название на каждом языке. Обязателен только основной язык; пустое поле перевода удаляет перевод.
- Нет перевода — показывается текст основного языка. hreflang: у списков — все языки, у записи — только языки,
  на которые она переведена.
- Строки сайта («Читать дальше», «Рубрика: …» и т. д.) встроены для `ru` и `en` и переопределяются словарём i18n
  ключами `blog.<ключ>`: `title`, `read_more`, `category`, `tags`, `category_title`, `tag_title`, `empty`,
  `newer`, `older`, `page_of`, `pagination`, `all_posts`, `not_found`, `not_found_text`.

## Ограничения

- Одновременная правка из двух вкладок: побеждает последнее сохранение.
- Markdown допускает HTML (как в страницах ядра) — админ доверенный.
- `<html lang>` ставит ядро по текущему языку, в том числе для записи без перевода.
- Нет RSS, комментариев, поиска, обложек записей.

## Тесты

```sh
php tests/run.php /path/to/motorchk/public_html/core     # или MOTORCHK_CORE=...
MOTORCHK_I18N=/path/to/i18n php tests/run.php ...        # с i18n (по умолчанию ../i18n рядом)
```

Тесты самодостаточны: временный сайт во временной папке, ядро с `vendor/`.

## Релиз

`./release.sh` проверяет чистое дерево и запись версии в `CHANGELOG.md`, ставит тег `vX.Y.Z` (если его нет)
и собирает `dist/blog-X.Y.Z.zip` из тега. `./release.sh --push` — ещё и пушит тег; GitHub Actions
(`.github/workflows/release.yml`) по тегу гоняет тесты и публикует Release с архивом.
